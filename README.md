# GeoLists

Веб-приложение для списков географических точек Санкт-Петербурга. Данные списков хранятся в IndexedDB; карта переключается между OpenFreeMap и полностью локальным архивом Protomaps PMTiles.

## Разработка

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Vite-режим удобен для разработки, но не предоставляет API обновлений. Полный локальный запуск:

```bash
npm run build
npm run serve
# http://127.0.0.1:4173
```

## Источник офлайн-карты для дистрибутива

Скрипт использует официальный `pmtiles` CLI и команду `extract` для выборочного получения прямоугольника Санкт-Петербурга из ежедневной сборки [Protomaps Basemap](https://docs.protomaps.com/basemaps/downloads). Весь планетарный архив не скачивается. Стандартные публичные tile-серверы OpenStreetMap не используются.

Эти шаги выполняет оператор дистрибутива, а не обычный пользователь:

1. Установите [pmtiles CLI](https://docs.protomaps.com/pmtiles/cli).
2. Найдите существующую дату сборки на [maps.protomaps.com/builds](https://maps.protomaps.com/builds/).
3. Подготовьте региональный архив:

```bash
BUILD_DATE=20261012 npm run map:prepare
npm run build
npm run serve
```

`map:prepare` извлекает bbox `29.40,59.63,31.05,60.25` до zoom 15 в `data/maps`, запускает `pmtiles verify`, считает SHA-256 и создаёт используемый сервером указатель `active.json`. Границы можно переопределить через `SPB_BOUNDS`. Скрипт также получает из [protomaps/basemaps-assets](https://github.com/protomaps/basemaps-assets) необходимые локальные диапазоны Noto Sans (Latin, Cyrillic и пунктуация) и их лицензию. После сборки офлайн-стиль не содержит внешних URL: здания, дороги и подписи читаются только с `127.0.0.1`.

Архивы и активный указатель исключены из Git намеренно. Можно вручную положить совместимый архив в `public/maps/spb.pmtiles`, но такой режим не имеет метаданных версии и не подходит для управляемых обновлений.

## Публикация карты и манифеста

Для первой пользовательской установки и последующих обновлений нужен небольшой JSON-манифест на контролируемом HTTPS-хостинге и подготовленный региональный PMTiles. Архивы и `active.json` не коммитятся в Git.

Однократная публикация через GitHub Releases:

1. Создайте Release в GitHub для репозитория GeoLists.
2. Прикрепите `data/maps/spb-<версия>.pmtiles` как release asset и дождитесь окончания загрузки.
3. Откройте ссылку скачивания asset в браузере и скопируйте её фактический HTTPS-адрес. Не составляйте адрес вручную: имя владельца, тег или asset могут отличаться.
4. Сгенерируйте манифест из того же локального файла:

```bash
npm run map:manifest -- \
  --archive data/maps/spb-20261111.pmtiles \
  --version 20261111 \
  --url "$PUBLISHED_ARCHIVE_URL" \
  --output spb-latest.json
```

Генератор проверяет PMTiles v3, вычисляет фактические размер и SHA-256 и атомарно создаёт JSON:

```json
{
  "version": "2026-10-12",
  "url": "<фактический HTTPS-адрес release asset>",
  "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
  "size": 123456789
}
```

5. Прикрепите `spb-latest.json` к Release как asset с неизменным именем. Для TASK 005 ожидаемый URL — `https://github.com/serbium-labs/GeoLists/releases/download/map-spb-20261111/spb-latest.json`. Пока этот URL не возвращает JSON с HTTP 200, интеграция обновлений не считается опубликованной.
6. Запишите проверенный адрес манифеста в отслеживаемый файл `config/map-updates.json`:

```json
{
  "manifestUrl": "<фактический HTTPS-адрес опубликованного spb-latest.json>"
}
```

После выпуска дистрибутива обычному пользователю не нужна переменная окружения. `MAP_UPDATE_MANIFEST_URL` сохранена только как override для разработки и тестового окружения и имеет приоритет над конфигурационным файлом.

Для обновления карты создайте новый региональный архив, опубликуйте его как новый asset, снова запустите `map:manifest` с новой версией и фактическим URL, затем замените содержимое файла манифеста по постоянному URL. Если хранилище не позволяет заменять asset, опубликуйте новый манифест и обновите `config/map-updates.json` в следующем выпуске приложения.

«Проверить» сравнивает `version` с активной. «Скачать карту» при первой установке и «Скачать обновление» в дальнейшем передают скачивание Node.js-серверу, а не браузеру. Сервер потоково пишет данные в отдельный временный файл и показывает реальный прогресс. Затем он проверяет заявленный размер, SHA-256 и заголовок PMTiles v3; только после всех проверок переименовывает файл и атомарно заменяет `active.json`. При ошибке временный файл удаляется, а предыдущий архив остаётся активным. После успеха приложение автоматически выбирает локальный режим и открывает новый версионированный URL архива — сервер и страницу перезапускать не нужно.

Protomaps не публикует готовый стабильный URL именно для вырезки СПб: официальный источник — планетарная ежедневная сборка, а региональный артефакт создаёт и размещает оператор приложения.

## Первая установка обычным пользователем

В опубликованном дистрибутиве адрес манифеста уже находится в `config/map-updates.json`. Пользователь открывает GeoLists, в блоке «Источник карты» дожидается состояния «Карта доступна» и нажимает «Скачать карту». Интерфейс показывает версию, размер, проценты и скачанные байты, затем проверку SHA-256. После сообщения «Карта установлена и готова к работе» приложение само переключается на локальную карту. В дальнейшем GeoLists читает архив из `data/maps` и работает с ним без интернета; неудачная проверка обновлений не удаляет установленную карту.

В конфигурации TASK 005 указан опубликованный `spb-latest.json` из Release `map-spb-20261111`. URL манифеста и архив проверены интеграционным тестом: первая установка, SHA-256, активация, Range-запросы и повторный запуск в локальном режиме работают через сервер GeoLists.

## Офлайн- и онлайн-режимы

Выбранный режим сохраняется в `localStorage`. При старте в локальном режиме приложение не запрашивает онлайн-стиль. PMTiles, glyph PBF, JS и CSS обслуживаются локальным сервером; PMTiles читается Range-запросами. Онлайн-режим использует публичный стиль [OpenFreeMap Liberty](https://openfreemap.org/) и требует интернет для стиля, тайлов, шрифтов и спрайтов.

Для автономной работы после установки нужен локальный сервер: открытие `index.html` через `file://` не поддерживает корректные Range-запросы и API обновлений.

## Хранение, источники и лицензии

- Большой PMTiles хранится в файловой системе, а не IndexedDB/Cache API: браузерные квоты зависят от браузера и могут очищаться автоматически.
- Protomaps Basemap основан на OpenStreetMap и распространяется как Produced Work по ODbL; локальная карта показывает атрибуцию Protomaps и © OpenStreetMap contributors.
- Noto Sans glyphs распространяются по SIL Open Font License; лицензию скрипт загружает рядом с файлами.
- Для архива zoom 15 не следует ожидать деталей, доступных только на zoom 16+. Размер зависит от даты и bbox.
- Сервер слушает только `127.0.0.1`. Для общего доступа нужны TLS, авторизация и reverse proxy.
